# 游戏资产生成画布 实现计划

## 目标
创建一个 ReactFlow 驱动的 mini-app「游戏资产生成画布」，支持三种节点（文生图 / 编辑图片 / 图片预览），节点间连线传图，画布状态持久化到 configs，生成结果下载到 data 目录。

### 改动 3：三种自定义节点设计

**通用约定**
- 所有节点用 `Handle`（Position.Top 输入、Position.Bottom 输出，或 Left/Right）
- 节点 data 结构：`{ type, label, status, params, output, error, ... }`
- 节点产出写入 `data.output.images`（string[] URL）

**TextToImageNode（文生图）**
- 参数表单：prompt（textarea 必填）、model（下拉）、aspect（下拉 16:9/9:16/1:1/4:3/3:4）、size（下拉 1k/2k/4k）
- model 下拉预置（只放能安全命中工作流路由的）：
  ```
  gpt-image-1, gpt-image-2, gpt-image-1.5, gpt-image-1-mini,
  jimeng-5.0, jimeng-4.6, jimeng-4.5, jimeng-4.1,
  qwen-image-2.0-pro, qwen-image-2.0
  ```
  （避开 `dall-e-*`/`wanx*`，它们在工作流 run_code 路由里不命中任何分支）
- 执行：调用 `text_to_image` 工作流（id `d88dcb7c-7f5f-47c8-962c-89217a2c0ad6`），input = `{ prompt, model, aspect, size }`
- 完成后：取 end 节点 `output.result`（string[]），写入本节点 `output.images`，下载图片到 data，触发「沿连线自动推送」给下游

**EditImageNode（编辑图片）**
- 参数表单：prompt（textarea 必填）、model（下拉）、aspect、size
- images 来源：优先用上游通过连线推送的图，无连线时支持手动上传/粘贴 URL
- 执行：调用 `edit_image` 工作流（id `19f5f8a9-305d-43a6-9b05-584597213a8f`），input = `{ images, prompt, model, aspect, size }`
- 结果处理同文生图

**PreviewNode（图片预览）**
- 无参数表单，纯展示：接收上游推送的图片，网格展示（参考 masonry/ai_image_video 画廊），支持点击放大
- 输入 Handle 可接多个上游

### 改动 4：连线数据流（自动沿连线推送）

- 节点执行完成并写入 `output.images` 后，遍历「以本节点为 source 的所有 edges」，把 images 推给 target 节点：
  - target 是 EditImageNode → 写入其 `params.images`（作为 edit_image 工作流的 images 入参）
  - target 是 PreviewNode → 写入其 `output.images`（展示）
- 实现位置：`Canvas.jsx` 的 `onNodeGenerateComplete` 回调，读取 edges → 更新 target 节点 data → 触发持久化
- edge 颜色/样式用 MarkerType 美化，连线动效

### 持久化策略（保存到 configs，单写者）

- 服务端 `src/services/canvas.js`：
  ```js
  export default {
    save_canvas: ({ nodes, edges }, ctx) => {
      ctx.writeConfig('canvas.json', { nodes, edges, savedAt: Date.now() });
      return { ok: true };
    },
    load_canvas: (_p, ctx) => ctx.readConfig('canvas.json'),
  };
  ```
- 前端：节点变化时 debounce 调 `invokeService('save_canvas', { nodes, edges })`；初始化 `getConfig('canvas.json')` 恢复；订阅 `onConfigChanged` 多端同步
- 节点产出（图片 URL）也随画布状态一起存，刷新即恢复

### 工作流调用封装（utils/workflow.js）

```js
const BUILTIN_PLUGIN = '@agent-spaces/builtin';
const TOOL = 'execute_workflow_sync';

export async function runWorkflow(workflowId, input) {
  const res = await window.AgentSpaces.callPluginTool(
    BUILTIN_PLUGIN, TOOL,
    { workflow_id: workflowId, input, fault_tolerance: 'stop' },
    { meta: { workflowId } }
  );
  // res.steps 里找最后一个 type=end 的 step，取 output
  const endStep = [...res.steps].reverse().find(s => s.nodeType === 'end')
                 || res.steps[res.steps.length - 1];
  if (res.status !== 'completed') throw new Error(endStep?.error || res.status);
  return endStep?.output || {};
}
// 调用：runWorkflow(WF.text_to_image, { prompt, model, aspect, size }).then(o => o.result)
```

### 图片下载到 data（utils/storage.js）

```js
export async function downloadImages(urls, nodeId) {
  const local = [];
  for (let i = 0; i < urls.length; i++) {
    const name = `gen/${nodeId}-${Date.now()}-${i}.png`;
    try { await window.AgentSpacesUI.downloadFile(urls[i], name); } catch {}
    local.push(name);
  }
  return local; // 本地路径，用于画布引用
}
```
（节点展示仍用原始 URL，本地路径作备份/导出用）

## 不做的事
- 不改 workflow.json（工作流路由逻辑保持现状）
- 不实现异步轮询工作流（用同步 execute_workflow_sync，默认超时够文生图用）
- 不做 model 文本输入（按你的选择用下拉预置）
- 不引入 elks/dagre 自动布局库（保持依赖最小，节点位置用固定初始坐标 + 手动拖动；如需自动排列后续再加）

## 验收步骤指南（实现后给用户）
1. 重启 web 服务（让 react-renderer.tsx / ui-exports.ts 改动生效）+ 重建 mini-app index（让新 mini-app 被发现）
2. 打开「游戏资产生成画布」mini-app 预览页
3. 点工具栏「+ 文生图」→ 画布出现节点，填 prompt 选模型，点执行 → 节点显示生成图片
4. 加「+ 图片预览」节点，把文生图节点输出连到预览节点 → 预览节点自动显示图
5. 加「+ 编辑图片」节点，把文生图输出连到它 → images 自动带入，填 prompt 执行 → 生成新图
6. 刷新页面 → 画布节点/连线/产出全部恢复（验证持久化）
