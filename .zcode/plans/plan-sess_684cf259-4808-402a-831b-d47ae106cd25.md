## 目标
把 `UiSplitterDialog.jsx`(1662行) 拆为「主文件 state声明 + fabric初始化 + JSX」与 4 个功能 hook + 2 个普通模块函数。功能 100% 等价，公共契约(props)不变。用户已确认「中等粒度」。

## 拆分方案

### 共享模式：`useSplitterContext` 聚合 refs
新增 `src/components/ui-splitter/useSplitterContext.js` —— 导出 `createSplitterRefs()` 工厂（返回上面分析的 ~30 个 ref 对象字面量）。各 hook 接收一个统一的 `ctx` 对象（含 refs + 必要的稳定回调），避免参数爆炸。**这是普通函数，非 hook**，避免 hooks 规则约束。

### 4 个 hook + 2 个模块函数

| 文件 | 内容 | 依赖 |
|---|---|---|
| `useSplitterSlices.js` | 切片框 CRUD + 撤销重做 + 预览渲染 + 自动检测：`rects/clearRects/realBox/snapshot/addRect/updateHistoryButtons/pushHistory/applySnapshot/undo/redo/setColor/detectFor/detectAll/renderList/syncSplitData/deleteSelectedRects/clearAllRects/deleteRectAt` + 2 个 auto-detect effect | curState/computeOptions（主文件传入）|
| `useSplitterGrid.js` | 网格：`syncGuidesFromCanvas/clearGuides/renderGuideDistances/clearGuideDistances/renderGuides/restoreGridForCurrent/buildGridBoxes/applyGridSplit/scheduleGridSplit/enterGridMode/exitGridMode/applyGridSize` + gridMode切换 effect | renderList/pushHistory/clearRects（来自 slices hook 返回值）|
| `useSplitterCrop.js` | 裁切：`applyCrop` | renderList/updateHistoryButtons/enterGridMode + sourceRef |
| `useSplitterSave.js` | 保存：`handleSave` + `togglePicking/handlePickColor/toggleDrawMode/toggleExport`（轻量 toggle）| curState/snapshot |
| `bindSplitterFabricEvents.js`(普通函数) | `bindFabricEvents(fc, fabric, ctx, callbacks)` —— 185 行 fabric 事件绑定 | pushHistory/renderList/setColor/scheduleGridSplit/renderGuideDistances/clearGuideDistances |

### 主文件保留
- 所有 `useState` 声明（驱动 UI）
- refs 声明（用 `createSplitterRefs()` 一次性生成）
- `curState/syncSourceRef/computeOptions`（地基，所有 hook 依赖）
- fabric 初始化大 `useEffect`（~220行，逻辑重但难拆，保留）
- JSX return（~160行）
- 装配顺序（关键，TDZ）：
  ```

  ... useState ...
  const curState / computeOptions ...   // 地基
  ```

## 关键约束（防 TDZ / 闭包陷阱）
1. hook 调用顺序严格遵循主文件原有 useCallback 声明顺序；每个 hook 内部 useCallback 依赖数组照搬原依赖。
2. 共享 refs 走 `ctx` 对象，hook 内 `useCallback` deps 只列「主文件传入的稳定回调 + refs 对象本身（refs 是稳定引用，不重建）」。
3. 不引入新的 state（state 全留主文件，避免 hook 间 state 同步问题）。
4. `createSplitterRefs()` 在组件体内调用一次（返回的对象在组件生命周期内稳定，等同原 useRef 行为）—— 实现为 `useRef` 包裹工厂结果，保证只创建一次。具体：主文件用 `const refsRef = useRef(null); if (!refsRef.current) refsRef.current = createSplitterRefs();`，然后 `const refs = refsRef.current;`，各字段原本就是 `useRef`，这里改为普通 `{current:...}` 也能等价工作，因为 fabric 回调闭包读的是 `.current`。**关键校验点**：原代码 refs 用 useRef，改工厂后行为必须一致（闭包读 `.current`，赋值写 `.current`），无 useMemo/useEffect 依赖差异。

## 不做的事
- 不改任何 props、不改 4 个已拆子组件、不动 helpers
- 不新增 state、不改算法逻辑（仅搬迁 + 参数化）
- 不动 fabric 初始化大 effect 的逻辑（仅把其中的 `bindFabricEvents`/键盘 effect 调用替换为模块函数）

## 风险与验证
- 主要风险：hook 间回调引用错位导致 `x is not defined`。缓解：每个 hook 显式 return 接口对象，主文件解构；babel 自检只查语法不查引用，故**改完后必须在浏览器跑通验收清单**。
- babel 语法自检所有新/改文件（含 jsx）。
- 浏览器验收：见下。
