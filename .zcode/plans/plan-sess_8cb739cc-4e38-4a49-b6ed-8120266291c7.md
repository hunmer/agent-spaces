# RunningHub 插件开发计划

## 目标
按 plugin-guide.md 规范创建 `runninghub` server 插件，覆盖 RunningHub 全部 API，共 **8 个节点**（6 管理 + 2 视频聚合），函数高度复用。

## 目录结构
```
packages/templates/plugins/runninghub/
├── info.json          # 插件元信息 + apiKey/baseUrl 配置
├── main.js            # activate(context) → registerActions(actions)
├── actions.js         # 工厂函数 (t) => [...]，8 个 action 定义
├── shared.js          # 复用：鉴权、baseUrl、postJson 封装、轮询函数
├── workflow.js        # 兼容空入口 { nodes: [] }
├── tools.js           # 兼容空入口 { tools: [] }
├── lang.json          # zh/en 文案
└── icon.png           # 插件图标(占位，复用现有样式)
```

## 复用设计（shared.js）
- `getBaseUrl(args)` → 默认 `https://www.runninghub.cn`
- `getHeaders(args)` → 注入 `Authorization: Bearer <apiKey>`，缺失抛错
- `postJson(ctx, path, args, body, timeout)` → 统一封装 ctx.api.postJson + 鉴权
- `pollTask(ctx, args, taskId, {timeoutMs, pollMs, t})` → **核心复用**：轮询 `/task/openapi/outputs`，按 `code` 判断状态（0成功取 data[].fileUrl / 804运行 / 813排队 / 805失败），新旧两套任务体系通用
- 返回结构统一为 `{ success, message, data: { outputs:[{url,type}], taskCostTime } }`

## 8 个节点（action 定义）

### 任务管理类（旧版 /task/openapi/* 体系）
1. **runninghub_comfyui_create** — 发起 ComfyUI 任务（高级版 `/task/openapi/create`）
   - 入参：workflowId、nodeInfoList(object[])、accessPassword、webhookUrl、addMetadata、instanceType、retainSeconds
   - 行为：提交后自动 pollTask 轮询到底，返回 outputs
2. **runninghub_aiapp_run** — 发起 AI 应用任务（`/task/openapi/ai-app/run`）
   - 入参：webappId、nodeInfoList(object[])、accessPassword、instanceType、webhookUrl
   - 行为：提交后自动 pollTask
3. **runninghub_task_outputs** — 查询任务结果（`/task/openapi/outputs`）
   - 入参：taskId
   - 行为：单次查询返回当前状态与结果（不轮询），供手动检查
4. **runninghub_task_cancel** — 取消任务（`/task/openapi/cancel`）
   - 入参：taskId

### 资源管理类
5. **runninghub_resource_list** — 获取公共模型列表（`/openapi/v2/resource/list`）
   - 入参：resourceType(UNET/CHECKPOINT/LORA/GGUF)、resourceName、baseModels(string[])、tags(number[])、current、size
6. **runninghub_workflow_json** — 获取工作流 JSON（`/task/openapi/getJsonApiFormat`）
   - 入参：workflowId

### 模型 API 视频生成（v2 体系，聚合下拉）
7. **runninghub_image_to_video** — 图生视频（按能力聚合）
   - model 下拉聚合全部图生视频变体（Vidu/可灵/海螺/万相/seedance/SkyReels/ltx/悠船/happyhorse 等共 60+ SKU），value 存 API 路径片段如 `vidu/image-to-video-q2-pro`
   - 通用入参：prompt、imageUrl、duration、resolution、aspectRatio、movementAmplitude、bgm（各模型差异通过 run 内按 model 分支处理，缺省字段给默认值）
   - 行为：POST `/openapi/v2/<path>`，返回 taskId 后 pollTask 轮询
8. **runninghub_reference_to_video** — 参考生视频（按能力聚合）
   - model 下拉聚合全部参考生视频变体（共 15+ SKU）
   - 通用入参：prompt、imageUrls(string[])、aspectRatio、resolution、duration、movementAmplitude
   - 行为：同上

## 多语言（lang.json）
zh/en 双语，key 命名遵循规范：`category`、`action.<name>.label/description`、`field.<name>.label/tooltip`、`message.<name>`。fallback 一律英文。

## 关键技术决策
- **统一轮询端点**：经文档核实，v1/v2 任务都用 `/task/openapi/outputs` 查询（v2 文档提及的 `/openapi/v2/query` 系个别文档笔误，官方示例统一走 outputs）。一个 pollTask 函数通吃。
- **dataType 显式标注**：所有 property 都写 dataType（nodeInfoList→object[]、imageUrls→string[]、tags→number[] 等），确保 tool schema 正确生成。
- **__config__ 默认值**：apiKey/baseUrl 默认 `{{ __config__["workflow.runninghub"]["apiKey"] }}`，与 minimax 一致。
- **无外部 npm 依赖**：纯 Node fetch（经 ctx.api），不需要 package.json。
- **节点 1/2/7/8 自动轮询，3 不轮询**：满足"自动轮询到底"需求，同时保留独立查询节点供灵活使用。
