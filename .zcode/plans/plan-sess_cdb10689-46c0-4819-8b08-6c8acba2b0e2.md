## 改动总览
给 `callPluginTool` 增加 `enabledPlugins` 白名单校验，前端 host api 前置拦截 + 后端 `plugin.ts` 路由权威兜底。严格白名单：`manifest.json` 未声明 `enabledPlugins` 或为空数组 → 全部 plugin 调用被拒；`@agent-spaces/builtin` 同样需要显式声明（与 `services/mini-app-agent.ts:350` 现有语义一致，fitting-room 样本就是这么做的）。

## 1. 前端：`packages/web/src/components/mini-apps/use-mini-app-host-api.tsx`

**(a) 新增 ref 缓存当前 mini-app 的 enabledPlugins**
- 在 effect 内（`projectId` 变化时）拉一次 `sdk.miniApp.get(projectId)`，把 `enabledPlugins ?? []` 存入一个新 ref（如 `enabledPluginsRef`），加载前置位 `null`。
- effect cleanup 时重置回 `null`（和 `configCacheRef` 一样）。
- 选缓存而非每次调用都拉：`enabledPlugins` 改动频率极低，且后端有权威校验兜底；用户改完 manifest 刷新页面即生效。

**(b) 在 `executePluginTool`（303-333 行）顶部加校验**
- 若 ref 仍为 `null`（首次未加载完），先 `await sdk.miniApp.get(projectId)` 兜底拉一次并回填 ref。
- 校验 `pluginId ∈ enabledPluginsRef.current`，不通过则直接返回 `{ error: 'Plugin "<pluginId>" is not enabled in this mini-app' }`（与后端错误格式一致），不发 HTTP。
- 校验放在生成 taskId / 发请求之前。

## 2. 后端：`packages/server/src/routes/plugin.ts`（135-200 行 `/:pluginId/tools/execute`）

**(a) 引入** `getProject` from `../services/mini-apps.js`（已处理 not found 抛错）。

**(b) 在 `name` 必填校验之后、`track` 编排之前插入校验**
- 仅当 `workspaceId` 存在时触发：`try` 读取 `getProject(workspaceId)`；
  - 读到 → 校验 `pluginId ∈ (project.enabledPlugins ?? [])`，不在则 `res.status(403).json({ error: 'Plugin "<pluginId>" is not enabled for mini-app "<workspaceId>"' })` 并 return；
  - 抛 not found（非 mini-app 场景）→ 跳过校验，保持向后兼容。
- 校验对 `BUILTIN_PLUGIN_ID` 一视同仁，不做特判。

## 边界与影响面
- 无 `enabledPlugins` 字段的现有 mini-app（workflow-miniapp、notion-database 等）调用 plugin 会被拒——这是用户明确选择的「严格白名单」语义；需要这些 mini-app 继续用 plugin 就得在 manifest 里补 `enabledPlugins`。
- 前端缓存策略：effect 内一次性拉取，运行中改 manifest 需刷新页面；后端每次请求实时读 manifest，是权威方。
- `agent_run` 等内置工具仍走 `BUILTIN_PLUGIN_ID`，同样受白名单约束（与 `runMiniAppAgent` 既有范围一致）。

## 验收步骤指南
1. 挑一个 `enabledPlugins` 为空/无此字段的 mini-app（如 workflow-miniapp），在其代码里调 `AgentSpaces.callPluginTool('某plugin', '某tool', {})` → 前端应直接返回 `{ error: 'Plugin ... is not enabled ...' }`，Network 里看不到 `/api/plugins/.../tools/execute` 请求。
2. 直接用 curl/Postman 绕过前端打 `POST /api/plugins/<pluginId>/tools/execute`（带 workspaceId=该 mini-app id）→ 返回 403 `{ error: 'Plugin ... is not enabled ...' }`。
3. 在该 mini-app 的 `manifest.json` 补上 `"enabledPlugins": ["<pluginId>"]`，刷新页面 → 同一个调用应正常执行。
4. 用 fitting-room（已声明 `["@agent-spaces/builtin"]`）跑一次 agent_run / 内置工具 → 正常工作，无回归。

## 后续优化
- 若后续希望「无字段 = 全允许」可配，可加一个服务端全局开关；当前严格白名单符合本次需求。
- 前端 enabledPlugins 缓存可加 WS 变更推送（类似 `miniApp.configChanged`）实现实时刷新，避免改完 manifest 必须刷新页面。
