## 实现目标
在 electron 包加一条 `setup-server` 运行脚本，并新增一个「安装引导页」：检测全局是否安装 `agent-spaces-server` —— 未装则显示一键安装+进度；已装但未运行则自动启动；就绪后跳转到 `http://localhost:3100`（其实是引导用户进入主应用）。

## 架构决策（已与用户确认）
- **页面放 `packages/web/src/app/setup/`**（Next 路由），随 `NEXT_STATIC_EXPORT=1 next build` → `scripts/copy-web.mjs` 自动进入 `packages/electron/renderer`，与项目现有架构（login、server-manager-dialog）一致。复用现有 shadcn/tailwind。
- **安装源**：默认 npmmirror（`https://registry.npmmirror.com`），与文档「快速安装（推荐）」一致。
- **页面仅在 Electron 环境显示全部能力**：通过 `window.electronAPI.isElectron === true` 判断；非 Electron（浏览器访问）时只显示文档指南，不暴露安装/启动按钮。

## 改动清单（6 处，最小改动）

### 1. `packages/electron/package.json` — 新增运行脚本
```json
"setup-server": "electron ."
```
> 与现有 `start` 同义但语义清晰：专门用于触发「检测→安装/启动→跳转」流程。配合下方 main 启动逻辑，启动后默认检测 server 状态。

### 2. `packages/electron/services/server-launcher.ts`（新建）
核心服务，模块级持有子进程句柄。职责：
- `isServerBinaryInstalled(): Promise<boolean>` — 跨平台检测全局命令是否存在。
  - Windows：`where agent-spaces-server`；非 Windows：`which agent-spaces-server`，用 `execFileSync`，捕获退出码判断。
- `getInstallStatus()` / `installServer(opts)` — 通过 `spawn` 执行 `npm i @agent-spaces/server -g --registry=https://registry.npmmirror.com`，把 stdout/stderr 按行经 IPC `setup:install-progress` 推给渲染进程；成功/失败发 `setup:install-done`。
- `isServerRunning(): Promise<boolean>` — `fetch('http://127.0.0.1:3100/api/health')` 判活（10s 超时，复用 server-manager-dialog 的探测思路）。
- `startServer(): Promise<void>` — `spawn('agent-spaces-server', [], { env: { ...process.env, PORT:'3100', HOST:'127.0.0.1' }, stdio:['ignore','pipe','pipe'], windowsHide:true, detached:false })`，存到模块级 `serverChild`；轮询 `/api/health`（间隔 500ms，最多 ~60 次）确认就绪。
- `registerServerLauncherIpc()` — 注册 IPC：
  - `setup:checkStatus` → `{ installed, running }`
  - `setup:install` → 触发 `installServer`
  - `setup:start` → 触发 `startServer`
  - 事件 `setup:install-progress`（line:string）、`setup:install-done`（{success,error}）、`setup:server-log`（line:string）
- 进程清理复用 main.ts 现有 `before-quit` 模式：导出 `stopServer()`，在 `app.on('before-quit')` 调用 `serverChild?.kill()`。

### 3. `packages/electron/preload/index.ts` — 暴露 setup API
在 `electronAPI` 加 `setup` 命名空间：
```ts
setup: {
  checkStatus: () => ipcRenderer.invoke('setup:checkStatus'),
  install: (registry?: string) => ipcRenderer.invoke('setup:install', registry),
  start: () => ipcRenderer.invoke('setup:start'),
  onInstallProgress: (cb) => { /* ipcRenderer.on('setup:install-progress') */ return unsubscribe },
  onInstallDone: (cb) => { ... },
  onServerLog: (cb) => { ... },
},
```

### 4. `packages/electron/main.ts` — 集成启动器
- import `registerServerLauncherIpc, stopServer`。
- 在 `registerFsIpcHandlers()` 之后调用 `registerServerLauncherIpc()`。
- `app.on('before-quit', ...)` 中加 `stopServer()`（与现有 `rendererServer?.close()` 同处）。
- **不改 window 加载流程**：生产态仍加载本地 renderer `/index.html`（即 web 首页），由前端在 `/` 自动判断是否需要引导跳 `/setup`（见下方第 6 点）。这样最小改动，不动 main 的 createWindow 逻辑。
- 开发态：`dev` 脚本不变（直连 3000）；用新增的 `setup-server` 脚本在生产构建产物上跑流程验证。

### 5. `packages/web/src/app/setup/page.tsx`（新建）+ `setup-helper.ts`
**page.tsx**：复用 login 页的两栏网格风格（左操作+右 hero），纯 client 组件。
- 顶部 logo + 标题「初始化 Agent Spaces Server」。
- 状态机展示（轮询 `electronAPI.setup.checkStatus()`，2s 一次）：
  1. 未安装 → 显示「一键安装」按钮 + 安装源下拉（默认 npmmirror，可切官方源）+ 进度日志区（`onInstallProgress` 推送的 npm 输出行）。
  2. 安装中 → 禁用按钮 + 实时日志 + 进度提示（基于 npm 输出关键字粗估，如 `added`/`packages`）。
  3. 已安装未运行 → 自动 `electronAPI.setup.start()`，显示「正在启动…」+ server 日志（`onServerLog`）。
  4. 已运行 → 显示「服务已就绪」+「进入 Agent Spaces」按钮，点击 `window.location.href = '/'`（SDK 默认连 127.0.0.1:3100）。
- 安装完成（`onInstallDone` success=true）后自动进入「已安装未运行」分支，触发启动。
- 非 Electron 环境（`window.electronAPI?.isElectron !== true`）：降级为只展示文档指南（环境要求、`npm i @agent-spaces/server -g`、`agent-spaces-server` 命令、参考 `documents/docs/getting-started/installation.mdx` 的内容），提供「打开安装文档」外链。

**setup-helper.ts**（或 inline）：抽 `isElectronEnvironment()` 到 `packages/web/src/lib/electron.ts`，供 setup 页和未来其他页面复用（现在 workflow-execution-input-dialog.tsx 里有重复实现）。

### 6. `packages/web/src/middleware.ts`（新建，可选但推荐）
> 现状：项目无 middleware.ts，未登录靠 SDK `onUnauthorized` 跳 `/login`。
- 仅在 Electron 环境（通过 cookie/user-agent 难判，但可在 SSR 时读 `NEXT_STATIC_EXPORT` 跳过）——**实际改用前端方案更简单**：在 `src/app/page.tsx` 顶部加一个 client gate，若 `isElectronEnvironment()` 且 `localStorage` 标记 `setup-completed !== 'true'`，则 `router.replace('/setup')`。
- setup 完成写入 `localStorage['setup-completed'] = 'true'`，避免重复引导；用户可手动访问 `/setup` 重新进入。
- **此点为可选增强**，若担心改动 page.tsx 影响非 Electron 用户，可改为「用户首次点击应用内某入口进 setup」；默认按可选增强实现，最小侵入（仅 page.tsx 顶部 4 行 gate）。

## 不改动的内容
- 不改 tsconfig（`services/**/*.ts`、`utils/**/*.ts` 已覆盖，新文件放 `services/`）。
- 不改 dependencies（全用 node 内置 `child_process`/`http`，web 复用现有 shadcn）。
- 不改 `scripts/copy-web.mjs`（Next 自动导出 setup 路由）。
- 不改 main.ts 的 createWindow / rendererServer 逻辑（仅追加注册和清理）。

## 验收（用户操作步骤）
1. `pnpm --filter @agent-spaces/electron build` —— 编译应通过（新增 server-launcher.ts 无类型错误）。
2. 全量构建 web：根目录 `pnpm build`（带 `NEXT_STATIC_EXPORT=1`）—— `packages/electron/renderer/setup.html` 应存在。
3. `cd packages/electron && pnpm start`（或新脚本 `pnpm setup-server`）—— 启动 electron。
4. 若本机未全局装 server：应自动停在 `/setup`，点「一键安装」看 npm 日志滚动；装完自动启动并出现「进入」按钮。
5. 若已装未跑：自动启动后跳主应用。
6. 若已跑：直接显示「服务已就绪」→ 进入。
7. 浏览器直接访问 `http://127.0.0.1:<renderer-port>/setup` —— 应降级显示纯文档指南，无安装/启动按钮。
