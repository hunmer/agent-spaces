# 节点高度按表单内容自适应

## 根因
节点创建时（`Canvas.jsx:246 createNodeAt`）用 `DEFAULT_SIZE` 写死固定 height（textToImage/editImage 240、imageDisplay 240、note 120），ReactFlow 节点高度由 `node.height`/`node.style.height` 决定，**不会自动跟随内容**。NodeShell 的内容区 `flex-1 overflow-auto` 只是溢出滚动，高度仍是固定值。

## 方案（仅首次自适应，之后手动 resize 不覆盖）
在 **NodeShell** 里用 `ResizeObserver` 测量「标题栏 + 内容区」的真实高度，**首次得到非零值后立即 disconnect 并上报一次**；Canvas 收到后更新该节点 height。因 NodeShell 首次测量后永不再上报，用户之后的 NodeResizer 拖拽不会被覆盖。

> 绕开 ReactFlow 内部初始 dimensions 测量的干扰：不依赖 onNodesChange 判断「用户是否 resize」，而是 NodeShell 端「只触发一次」，从源头杜绝冲突。最小改动、零误判。

## 改动清单（4 个文件）

### 1. `src/components/nodes/NodeShell.jsx`
- 新增 prop `id`
- 根 div 加 `ref={rootRef}`
- 标题栏 div 加 `data-node-header`，内容区 div 加 `data-node-content`
- 新增 `useLayoutEffect` + `ResizeObserver`：
  - `measuredRef`（仅一次门控）
  - 计算 `h = headerEl.offsetHeight + contentEl.scrollHeight + 2`（+边框）
  - 非零且稳定 → `measuredRef.current=true`、`ro.disconnect()`、调 `data.onAutoSizeToContent(id, h)`
  - 回调不存在（`data.onAutoSizeToContent` 未注入）则不测量

### 2. `src/components/Canvas.jsx`
- 新增 `handleAutoSizeToContent(nodeId, height)`：
  - 限幅 `[120, 800]`
  - `setNodes` 只更新对应节点 `height` + `style.height`（保留原 width）
- `decoratedNodes` 注入 `onAutoSizeToContent: handleAutoSizeToContent`（与现有 `onAutoSize` 并列）

### 3. 节点组件（3 个，各加一个 `id={id}` 传给 NodeShell）
- `TextToImageNode.jsx`、`EditImageNode.jsx`、`ImageDisplayNode.jsx`
  - 这三个组件已解构 `{ id, data, selected }`，只需在 `<NodeShell ...>` 上补 `id={id}`

### 4. 不改动
- `NoteNode.jsx`：便签，`resize-y` textarea 用户可手动拉，且固定 200×120 对纯文本足够，保持现状
- `DEFAULT_SIZE`：保留作为首次测量前的占位尺寸（避免画布闪空），测量后覆盖
- imageDisplay 的图片 `onAutoSize`（图片 onLoad 按自然尺寸）：保持原逻辑，与内容首测不冲突（首测 loading 态 → 图片加载后 onAutoSize 覆盖为图片尺寸）

## 验收
- 插入「文字生成图片」「编辑图片」节点：高度自动贴合表单（提示词库按钮 + textarea + 3 个下拉 + 生成按钮），无大段空白、无内容被截断滚动
- 拖拽 NodeResizer 手动改高度后，再次切换/操作不被自动重置
- 切换工作区再切回：节点高度保持（已持久化到 canvas.json）
- 便签节点行为不变
- 语法自检：`node --input-type=commonjs -e "require('@babel/standalone').transform(require('fs').readFileSync('NodeShell.jsx','utf8'),{presets:['react']})"`
