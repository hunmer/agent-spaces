## 方案概要

给 `media-gallery.tsx` 的 **lightGallery 全屏预览弹窗** 增加「右上角自定义按钮(actions)」能力,作为**可选参数**向下兼容;fitting-room/GalleryPage 改用 `openMediaGallery` 做图片预览(替代当前的 `window.open`),并传入「收藏到素材库 / 导入到画布」两个按钮(Toast 占位)。game-asset-canvas 现有 15 处调用零改动(第 3 参数可选,缺省 = 不显示按钮)。

## 改动 1:`packages/web/src/components/ui/media-gallery.tsx`(宿主层,需重启 web)

### 1a. `MediaItem` 类型不变(已有 `src/thumb/type/alt/fileName`)。

### 1b. 新增类型 `MediaGalleryAction`(放文件顶部类型区):
```ts
export type MediaGalleryAction = {
  label: string          // 按钮文字
  onClick: (info: { item: MediaItem; index: number }) => void
  icon?: React.ReactNode
  variant?: 'default' | 'outline' | 'ghost'  // 映射 Button variant,默认 'outline'
}
```

### 1c. `MediaGallery` 组件签名扩展(第 51 行):
```ts
{ items, className, actions, startIndex = 0 }: {
  items: MediaItem[]
  className?: string
  actions?: MediaGalleryAction[]      // 新增,可选
  startIndex?: number                 // 新增,可选,默认 0
}
```
在 lightGallery 初始化时:
- 配置加 `index: startIndex`
- 注册 `lgBeforeOpen` 事件回调:取 `.lg-toolbar`,把 actions 渲染成一个容器插入到 toolbar 内(放 close 按钮左侧)。用 `createRoot` 挂 React 节点,卸载时清理。

### 1d. `openMediaGallery` 签名扩展(第 80 行),第 3 个可选参数:
```ts
export function openMediaGallery(
  items: MediaItem[],
  startIndex = 0,
  actions?: MediaGalleryAction[]      // 新增,可选
)
```
同样在 `lgBeforeOpen`/`lgAfterOpen` 注入 actions 到 `.lg-toolbar`。点击 action 时,通过 lightGallery 实例的 `data` 拿当前 index → 映射到 items[index] → 调 `onClick({item, index})`。`lgAfterSlide` 事件更新当前 index 引用(使 action 始终作用于当前可见图)。关闭(`lgAfterClose`)时 unmount React root 并清理 DOM 引用。

### 1e. 注入的按钮容器样式:
- 用 inline style 定位(`position:absolute; right:44px;` 留出 close 按钮位置,或 flex 排在 close 前),避免依赖 Tailwind class(lightGallery 弹窗在 document.body 下,不受项目 Tailwind 作用域保证)。
- 按钮用项目已有 `Button` 组件(`@/components/ui/button`),variant 取 `action.variant || 'outline'`,size `sm`,白色文字/半透明背景适配深色 toolbar。
- z-index 高于 toolbar(确保可点)。

### 1f. 关闭事件清理:
现有 `lgAfterClose` 已 `instance.destroy() + el.remove()`;新增逻辑在此前 unmount actions 的 React root(若 createRoot 创建过)。

## 改动 2:`fitting-room/src/components/GalleryPage.jsx`(mini-app,刷新即生效)

### 2a. 引入并解构:
```jsx
const { ..., openMediaGallery } = window.AgentSpacesUI;  // 第 4-13 行解构里加 openMediaGallery
```

### 2b. 两个点击 handler(放组件内):
- `handleAddToLibrary(item)` → `toast.info("收藏到素材库:待接入素材库能力")`(占位)
- `handleImportToCanvas(item)` → `toast.info("导入到画布:待接入画布能力")`(占位)
- 需从 `window.AgentSpacesUI` 解构 `toast` 和 `Toaster`

### 2c. 定义 actions 数组(组件内,useMemo 或常量):
```jsx
const galleryActions = [
  { label: "收藏到素材库", onClick: ({ item }) => handleAddToLibrary(item) },
  { label: "导入到画布", onClick: ({ item }) => handleImportToCanvas(item) },
];
```

### 2d. 替换图片点击行为(第 116 行 + 第 128 行):
当前:`onClick={() => window.open(item.url, "_blank")}`
改为:构建 `MediaItem[]`(history → `{src: item.url, thumb: item.thumbUrl, alt: item.prompt, fileName: item.id}`),点击调:
```jsx
onClick={() => openMediaGallery(mediaItems, index, galleryActions)}
```
底部「打开」按钮(128 行)保留 `window.open`(原行为,打开原图大图)。

## 改动 3:`fitting-room/src/index.jsx`(挂载 Toaster,mini-app,刷新即生效)

在解构(第 8 行)加 `Toaster`;在 `Root` 组件 JSX 里 `<App />` 同级挂一个 `<Toaster />`(供 toast 占位用)。

## 不改的地方(兼容性确认)
- game-asset-canvas 全部 15 处 `openMediaGallery` 调用**零改动**:第 3 参数 `actions` 可选,缺省 = 不注入按钮 = 行为与现状完全一致。
- stickerGenerator、eagle、rss_reader 等其他 mini-app 不动。
- `MediaItem` 类型字段不变,不破坏任何现有数据。

## 风险与回滚
- 唯一风险点是 lightGallery `.lg-toolbar` 注入时序:若 `lgBeforeOpen` 时 DOM 未就绪,改用 `lgAfterOpen`/`lgAfterAppendSubHtmlTo`。代码里做 `querySelector('.lg-toolbar')` 存在性兜底(取不到就跳过注入,不抛错)。
- createRoot unmount 在 `lgAfterClose` 内做,避免内存泄漏。
- 回滚:revert media-gallery.tsx + GalleryPage.jsx + index.jsx 三个文件即可。

## 验收步骤
1. 重启 web(因改了宿主层 media-gallery.tsx)。
2. 打开 fitting-room → 发型/服装历史页,点击任意历史图 → 弹出 lightGallery 全屏预览,右上角(close 左侧)显示【收藏到素材库】【导入到画布】两个按钮。
3. 点击按钮 → 右下角弹出 toast(占位提示)。
4. 左右切换图片后再点按钮 → toast 提示作用于当前可见图(index 正确)。
5. 关闭预览 → 再次打开 → 按钮仍在(无重复注入、无内存泄漏)。
6. 进 game-asset-canvas → 点任意生成记录/节点图片放大 → 全屏预览**无新按钮**(确认旧调用未受影响)。
