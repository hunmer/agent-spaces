# 新增「骨骼编辑器」节点 — 实施计划

## 技术决策（基于调研结论）

| 决策点 | 方案 | 理由 |
|---|---|---|
| **Spine 运行时** | `pixi.js@^7` + `@pixi-spine/all-4.0@4.0.6` | 该单一包**同时含 3.8 和 4.0 运行时**，peerDep 是 pixi v7。满足「两版本都支持」，且能直接复用参考仓库（用同款 `@pixi-spine/all-3.8`）的加载逻辑。不用 spine-pixi-v8（它只支持 4.x，且与 pixi-spine 不兼容） |
| **集成方式** | 独立 Vite SPA → 构建产物放 `src/vendor/spine-editor-web/` → `SpineEditorDialog` 用 iframe 加载 → postMessage 通信 | 完全复刻现有 `pixelEditor`/`directorDesk` 节点的成熟模式。mini-app 的 `src/file` 路由已验证支持任意深度子目录静态资源（director-desk-web/assets/ 即案例） |
| **角色库数据** | 克隆参考仓库 `src/assets/data/*.json`（mainData/factions/TypeClass/groupType）到 SPA，复刻 Filter.jsx 的「分组/职业/搜索/分页」过滤逻辑 | 用户明确要求克隆本地 JSON |

## 架构总览

```

┌─────────────────────────┐           ┌──────────────────────────────┐

│  - FileUpload(.skel...) │  iframe   │   index.html                  │

│  - 「打开骨骼编辑器」按钮 │           │   data/*.json (角色库)         │
│                         │  postMsg  │                               │
│ SpineEditorDialog.jsx   │ ◄──────── │  [角色库过滤] [骨骼树] [画布]   │
│  - 同源 URL 构造         │           │  [变换面板] [工具栏]           │
│  - ready/inject/export  │           │                               │
│  - dataUrl→uploadFile   │           │ 导出: pose JSON / 截图 png     │
└─────────────────────────┘           └──────────────────────────────┘
```

## postMessage 通信协议（SpineEditor 版）

父→iframe：
- `spine:inject-assets` `{skelDataUrl, atlasDataUrl, pngDataUrl, name}` 注入用户上传的 .skel/.atlas/.png（转 base64，绕跨域）
- `spine:inject-background` `{imageUrl}` 可选，上游图作背景

iframe→父：
- `spine:ready` 编辑器就绪 → 触发 inject
- `spine:export-pose` `{json, name}` 导出姿势 JSON（文本，直接回传不需 uploadFile）
- `spine:export-screenshot` `{dataUrl, name}` 导出截图 → 父端 uploadFile 转 http URL
- `spine:export-spine` `{files: [{name, dataUrl}]}` 导出完整 Spine 文件包 → 逐个 uploadFile
- `spine:close` 用户点关闭

## 实施步骤

### 第一部分：独立 Spine 编辑器 SPA（vendor/spine-editor-web/spine-editor-src/）

新建一个独立 Vite 工程（源码放 `spine-editor-src/`，构建后 dist 内容拷到 `vendor/spine-editor-web/`）：

**依赖**：`pixi.js@^7.3.3`、`@pixi-spine/all-4.0@4.0.6`（含 3.8+4.0 运行时）

**目录结构**（对齐 PRD 第 6.2 节）：
```
spine-editor-src/
├── package.json
├── vite.config.js          # base: './'，产出相对路径
├── index.html
├── src/
│   ├── main.js             # 入口，初始化 Pixi Application + 挂 postMessage 监听
│   ├── core/
│   │   ├── SpineEditorApp.js    # Pixi Application 封装（渲染循环、缩放平移）
│   │   ├── BoneGizmoLayer.js    # 骨骼手柄+连线（Graphics 绘制圆点和父子线，选中高亮）
│   │   ├── CoordinateUtils.js   # Spine↔Pixi 坐标转换
│   │   └── HistoryManager.js    # 撤销重做（快照栈，≥20 步）
│   ├── loaders/
│   │   └── SpineLoader.js       # 复刻参考仓库 UploadAssets.loadAssets（SkeletonBinary/TextureAtlas/AtlasAttachmentLoader），按 .skel 版本路由 3.8/4.0 parser
│   ├── ui/
│   │   ├── BoneTree.js          # 骨骼层级树（展开/折叠/点击选中/数量显示 N/M）
│   │   ├── TransformPanel.js    # X/Y/旋转/ScaleX/Y 输入 + 应用/翻转/重置按钮
│   │   ├── Toolbar.js           # 静态/播放切换、动画下拉、皮肤下拉、撤销重做、适应视图、导出
│   │   ├── AssetFilter.js       # 克隆参考仓库 Filter.jsx（分组/职业/搜索/分页）
│   │   └── StatusBar.js         # 底部状态（就绪/已修改）
│   ├── data/                    # 克隆自参考仓库
│   │   ├── mainData.json        # 角色库（碧蓝航线）
│   │   ├── factions.json        # 分组
│   │   ├── TypeClass.json       # 职业
│   │   └── GroupType.json       # 分组→职业映射
│   ├── exporters/
│   │   ├── PoseExporter.js      # 导出当前姿势 JSON
│   │   └── SpineFileExporter.js # 打包原始资源
│   └── styles.css
```

**核心功能实现要点**：
- 骨骼拖拽：`bone.x/bone.y`（左键）、`bone.rotation`（右键），拖拽后 `skeleton.updateWorldTransform()` + 刷新 Gizmo
- 选中同步：树点击 → `selectedBone` → Gizmo 高亮 + 面板刷新
- 模式切换：静态姿势（setup pose + 手动变换）vs 播放动画（`state.setAnimation`）
- 快捷键：Ctrl+Z/Y 撤销重做、空格+拖拽平移、滚轮缩放

### 第二部分：构建产物部署

- `cd spine-editor-src && npm install && npm run build`

### 第四部分：节点组件（2 个新文件）

**`components/nodes/SpineEditorNode.jsx`**（参考 DirectorDeskNode.jsx 结构）：
- FileUpload 接收 `.skel/.atlas/.png` 三件套（用 uploadFile 持久化 URL）
- 可选上游图片输入（作背景）
- 「打开骨骼编辑器」按钮 → 打开 Dialog
- 导出结果展示到 data.output.images

**`components/SpineEditorDialog.jsx`**（参考 PixelEditorDialog.jsx，~200 行）：
- 构造同源 iframe URL：`${origin}/api/mini-apps/${projectId}/src/file/vendor/spine-editor-web/index.html`
- 监听 `spine:ready` → 注入上传的 .skel/.atlas/.png（fetch→dataUrl→postMessage）
- 监听 `spine:export-screenshot` / `spine:export-spine` → uploadFile 转 http URL → onSave 回传节点
- 监听 `spine:export-pose` → 直接保存 JSON 文本（无需 uploadFile）
- 92vw×94vh 全屏 Dialog

## 验收标准

1. 新增节点 tab 出现「骨骼编辑器」卡片，能拖到画布
2. 上传 .skel/.atlas/.png → 打开编辑器 → iframe 正常加载（无白屏）
3. 角色库过滤器（分组/职业/搜索/分页）正常工作，点击角色能加载到画布
4. 骨骼树显示、点击选中高亮、左键拖拽移动、右键旋转
5. 变换面板编辑 X/Y/旋转/Scale 并应用生效
6. 静态/播放模式切换、动画/皮肤下拉可用、适应视图
7. 撤销重做（Ctrl+Z/Y）可用
8. 导出姿势 JSON / 截图 → 截图经 uploadFile 回传为节点产出，可连线下游

## 风险与限制

- **构建产物体积**：pixi.js v7 + pixi-spine 全家桶 gzip 后约 400-500KB，首次加载需几秒。可接受（director-desk 的 bundle 也是 1.3MB）
- **角色库版权**：克隆的碧蓝航线角色数据 JSON 是参考仓库的公开演示数据，仅作内置演示库。如需商用需替换
- **MVP 范围**：严格按 PRD 3.1 节 P0 功能实现；3.2 节「可选增强」（翻转/搜索/多选/关键帧）和 10 节「后续扩展」本次不做
- **.skel 二进制解析**：复刻参考仓库用 `SkeletonBinary` parser；若用户提供的是 .json 格式 Spine 文件，需额外加 `SkeletonJson` parser 分支（首版先支持 .skel，与参考仓库一致）
