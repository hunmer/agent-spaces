# Spine 动作录制 + 视频展示节点 实现方案

## 总体架构
```
Spine SPA(iframe)                    mini-app
┌──────────────────────┐  postMsg    ┌──────────────────────────┐
│ Toolbar [●录制]       │ ──────────► │ SpineEditorDialog        │
│ RecordManager        │ export-video│  → uploadFile → onExportVideo
│ (MediaRecorder+WebM) │             │ SpineEditorNode          │
└──────────────────────┘             │  → output.videos         │
                                     │  → 「导出到画布」         │
                                     │ VideoDisplayNode (新)     │
                                     │  <video controls>        │
                                     │  支持连线透传上游视频     │
                                     └──────────────────────────┘
```

## 改动清单(17 处)

### A. Spine SPA 录制(源码 `spine-editor-build/src/`,改完必须重新构建)
1. **`core/SpineEditorApp.js`** — `init()` 的 PIXI.Application 选项加 `preserveDrawingBuffer: true`(防 WebGL canvas 录制黑屏)。canvasElement 已是 public 字段,RecordManager 直接用。
2. **新增 `core/RecordManager.js`** — 封装 MediaRecorder:
   - `start({fps=30})`:校验 `canvas.captureStream(fps)` + `MediaRecorder`(优选 `video/webm;codecs=vp9`,降级 `video/webm`),收集 chunks
   - `stop()`:返回 Promise<dataUrl>(Blob→FileReader.readAsDataURL)
   - `isRecording` 状态 + 兼容性检测(浏览器不支持时报错)
3. **`ui/Toolbar.js`** — 导出组旁加录制按钮:
   - 回调解构加 `onToggleRecord`
   - HTML 加 `<button id="btn-record">● 录制</button>`,录制中切换文案「■ 停止」+ `.recording` 红点样式
   - 新增 `setRecording(bool)` 方法同步按钮状态
   - 录制开始时若处于 pose 模式,自动切到 play 模式(动作录制需动画推进)
4. **`main.js`** — 实例化 RecordManager,串联:
   - `toggleRecord()`:未录制→start(并把 mode 切 play);录制中→stop→拿 dataUrl→`postToParent('spine:export-video', { dataUrl, name: '${spineName}-${timestamp}.webm' })`
   - Toolbar 回调加 `onToggleRecord: toggleRecord`
   - 文件头协议注释补 `spine:export-video {dataUrl, name}`

### B. postMessage 父端(mini-app `src/`)
5. **`components/SpineEditorDialog.jsx`**:
   - props 加 `onExportVideo: (url) => void`
   - `onMsg` 加 `spine:export-video` 分支:照 screenshot 分支,dataUrl→fetch blob→`new File([blob], name, {type:'video/webm'})`→uploadFile→`onExportVideoRef.current?.(httpUrl)`
   - 协议注释更新
6. **`components/nodes/SpineEditorNode.jsx`**:
   - 加 `handleExportVideo(url)`:合并写 `output: { ...(现有output), videos:[url] }`(不覆盖 images),`status:'done'`
   - Dialog 传 `onExportVideo={handleExportVideo}`

### C. 视频展示节点(mini-app `src/`,参考 ImageDisplayNode)
7. **新增 `components/nodes/VideoDisplayNode.jsx`**:
   - props `{id, data, selected}`,读 `data.videos: string[]`
   - 自写 `<input type="file" accept="video/*">` + `AS.uploadFile` 上传,写回 `data.videos`
   - 渲染 `<video src={current} controls />`,多视频底部箭头切换
   - 双击全屏(`<video requestFullscreen>`)
   - NodeToolbar「导出视频」按钮 → `data.onExportVideos(videos)`
   - 空态虚线框 + 上传提示
8. **`utils/constants.js`** — `NODE_TYPES.videoDisplay='videoDisplay'` + `NODE_META[NODE_TYPES.videoDisplay]={label:'视频展示',icon:'🎬',color:'#8b5cf6'}`
9. **`utils/canvas-constants.js`** — import VideoDisplayNode + NODE_COMPONENTS + ADD_NODE_ITEMS + `DEFAULT_SIZE:{w:320,h:240}` + `initialData: {videos:[],source:''}`
10. **`api.js`** — VALID_NODE_TYPES 加 `'videoDisplay'` + NODE_LABELS 加 `videoDisplay:'视频展示'`
11. **`tools.js`** — NODE_TYPE_ENUM + NODE_TYPE_DESC 加 `'videoDisplay=视频展示（接收上游视频）'`
12. **`components/RightPanel.jsx`** — ADD_ITEMS 加 `{type:NODE_TYPES.videoDisplay,label:'视频展示',category:'media'}`

### D. 视频连线透传(对称图片逻辑,独立函数隔离风险)
13. **`utils/input-images.js`** — 新增 `computeInputVideos(nodes, edges)`(复制 computeInputImages 结构):
    - receiver 含 `videoDisplay`(透传)+ `videoGenerator`(消费,非透传)
    - `sourceVideos`:取 `output.videos`/`output.video`,videoDisplay 无 output 时透传 `data.videos`
    - 返回 `Map<id,{videos,isDisplay}>`
14. **`hooks/useDecoratedNodes.js`**:
    - 同时算 `upstreamVideos = computeInputVideos(nodes,edges)`
    - 有上游视频时注入 `data.videos` + `data.source='upstream'`
    - 注入 `onExportVideos: (vids) => onExportVideos?.(nd, vids)` 回调
    - videoDisplay 的 dragHandle 同款处理
15. **`components/Canvas.jsx`** — nodeTypes 映射加 `videoDisplay: VideoDisplayNode`;callbacks 加 `onExportVideos: handleExportVideosWithPicker`(复用图片同款 picker,只是造视频节点)

### E. 导出视频到画布
16. **`hooks/useImageOutputs.js`** — 新增对称视频函数:
    - `buildVideoNodes(prevNodes, urls, opts)`(照 buildImageNodes,用 videoDisplay 的 size/meta/initialData,`data:{videos:[url]}`)
    - `addVideoNodesFromUrls` + `handleExportVideos`(单视频独立节点,多视频分组)

### F. 构建产物
17. `cd spine-editor-build && npm run build`,把 `dist/index.html` 和 `dist/assets/` 拷到 `src/vendor/spine-editor-web/`(替换旧产物)

## 关键技术决策
| 点 | 方案 |
|---|---|
| 录制格式 | WebM(VP9),MediaRecorder 原生,无额外依赖 |
| 黑屏防护 | PIXI.Application 加 `preserveDrawingBuffer: true` |
| 录制模式 | 开始录制自动切 play 模式(pose 模式画面静止录不出动作) |
| 视频连线 | 新增独立 `computeInputVideos`,不碰图片逻辑(隔离风险,有少量重复但安全) |
| 导出到画布 | 复用图片 picker 流程,对称造 `buildVideoNodes` |
| output 字段 | SpineEditor 的 output 同时支持 images(截图)+ videos(录制),互不覆盖 |
| 传输 | 视频经 dataUrl postMessage → 父端 uploadFile 转 http URL(与 screenshot 同协议) |

## 验收步骤
1. 刷新页面 → 右侧「媒体」分类有「🎬 视频展示」卡片
2. 拖入骨骼编辑器节点 → 打开 → 选角色 → 切播放动画
3. 点「● 录制」→ 录几秒 → 点「■ 停止」→ 状态栏提示已回传
4. SpineEditorNode 产出区出现视频 → 点「导出到画布」→ 生成视频展示节点
5. 视频展示节点能播放、双击全屏、下载
6. 视频展示节点连线到另一个视频展示节点 → 下游能收到并播放(连线透传)
7. 视频展示节点单独上传本地视频 → 正常播放
