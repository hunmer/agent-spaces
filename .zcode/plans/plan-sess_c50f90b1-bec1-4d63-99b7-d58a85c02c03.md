## 改动范围
仅修改 `packages/templates/plugins/ai-image/actions.js`（main.js / tools.js / workflow.js 无需改动）。`ai_image_query_task` 节点不涉及图片生成，保持不变。

## 新增字段
在 `ai_image_generate` 和 `ai_image_edit` 两个节点的 `properties` 里（baseUrl 之后、prompt 之前）各加一个 select 字段：

```js
{
  key: 'apiMode',
  label: t('field.apiMode.label', 'API Mode'),
  type: 'select',
  dataType: 'string',
  default: 'async_task',
  options: [
    { label: '异步任务 (Images API)', value: 'async_task' },
    { label: 'Chat Completions', value: 'chat_completions' },
    { label: 'Responses', value: 'responses' },
  ],
  tooltip: t('field.apiMode.tooltip', 'async_task: /v1/images/generations 轮询；chat_completions: /v1/chat/completions 同步；responses: /v1/responses 同步。'),
}
```
兼容性：旧配置无 apiMode → `args.apiMode || 'async_task'` → 走原逻辑，零改动。

## run 分流
generate / edit 的 `run` 里按 `getApiMode(args)` 分流到三套提交+解析逻辑：

### 1. async_task（现有逻辑，原样保留）
不改。generate 走 `/v1/images/generations?async=true` + 轮询；edit 走 multipart `/v1/images/edits?async=true` + 轮询。

### 2. chat_completions（新增，同步）
- **generate 请求体**：`{ model, messages:[{role:'user', content: prompt}] }`，POST `${baseUrl}/v1/chat/completions`（用 `ctx.api.postJson`）。
- **edit 请求体**（图生图，多模态 messages）：
  ```js
  { model, messages:[{ role:'user', content:[
    { type:'text', text: prompt },
    ...images.map(b => ({ type:'image_url', image_url:{ url: bufferToDataUri(b) } })),
    ...(mask ? [{type:'image_url', image_url:{url: bufferToDataUri(mask)}}] : [])
  ]}] }
  ```
- **响应解析** `extractImagesFromChatContent(content, ctx)`：取 `choices[0].message.content`，按优先级提取图片——
  1. content 为数组 → 遍历取 `image_url.url`
  2. markdown 图片 `![..](url)` 正则
  3. 纯 http(s) 图片 URL
  4. base64 data URI
  - URL 直接收集；base64/data URI 落盘成 httpPath（复用 `ctx.api.savePublicFile`）。

### 3. responses（新增，同步）
- **generate 请求体**：
  ```js
  { model, input: prompt,
    tools:[{ type:'image_generation', ...(size && {size}) }] }
  ```
  `size` 由 `aspectRatioToSize(args.aspectRatio)` 映射（1:1→1024x1024，16:9→1536x1024，9:16→1024x1536，其余不传 size）。
- **edit 请求体**（图生图）：
  ```js
  { model, input:[{ role:'user', content:[
    { type:'input_text', text: prompt },
    ...images.map(b => ({ type:'input_image', image_url: bufferToDataUri(b) })),
    ...(mask ? [{type:'input_image', image_url: bufferToDataUri(mask)}] : [])
  ]}], tools:[{ type:'image_generation' }] }
  ```
- **响应解析** `extractImagesFromResponsesOutput(output, ctx)`：遍历 `response.output`，取 `type==='image_generation_call'` 的项 → `result`（b64_json）落盘；兜底取 `image_url`。
- model 语义说明：Responses 官方 model 是主对话模型（gpt-4o/gpt-5.6），但中转服务通常也接受 gpt-image-1 等图片模型名直接处理，故 model 字段含义不变、直接透传，避免新增字段。

## 新增工具函数（actions.js 顶部工具区）
- `getApiMode(args)` → `args.apiMode || 'async_task'`
- `bufferToDataUri({buffer, mime})` → `data:${mime};base64,${buffer.toString('base64')}`
- `aspectRatioToSize(ratio)` → 返回标准 size 字符串或 `''`
- `runChatCompletions(ctx, args, body)` → postJson + 解析，返回 `{ images, model, created }`
- `runResponses(ctx, args, body)` → postJson + 解析，返回 `{ images, model, created }`
- `extractImagesFromChatContent(content, ctx)` → 图片数组
- `extractImagesFromResponsesOutput(output, ctx)` → 图片数组

## outputs 结构
不变。chat/responses 模式无 taskId → 置空字符串；created 从响应里取（chat 的 `response.created`，responses 的 `response.created` 或 `response.output[].created`）。

## 验收
- 旧配置（无 apiMode）默认走 async_task，行为与改动前完全一致。
- 切换到 chat_completions / responses，配置 apiKey + baseUrl + prompt(+图片) 后能正确发请求并解析图片。
- 图生图节点 chat/responses 模式支持多参考图输入。

## 风险
- chat 模式从 content 解析图片依赖中转服务返回格式，已按常见中转（markdown/url/base64）兜底；若某中转格式特殊，后续可再适配。
- responses 的 size 映射仅覆盖 OpenAI 标准比例，非标准比例不传 size（由模型默认处理）。
