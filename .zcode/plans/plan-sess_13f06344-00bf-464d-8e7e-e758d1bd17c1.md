## 目标

在 `workspace-shell.tsx` 中新增两个 tab：
- **`cli-list`**（左侧 tabset）：展示独立的 CLI 会话列表（新增/选择/删除/重命名）
- **`cli-panel`**（右侧 tabset）：激活会话后，用 `FlexLayoutShell` 展示该会话独有的终端布局；默认一个 `SingleTerminal`；工具栏「+」下拉展示已检测到的 CLI，点击即开新终端并自动执行 CLI 命令

每个 cli-list 项 ↔ 一个 cli-panel ↔ 一份独立 localStorage 的 flex-layout 数据。

## 关键设计决策（已与用户确认）

1. **会话来源**：全新独立的 CLI 会话模型（不复用 terminal sessions / issue 列表）
2. **布局隔离**：每个会话用独立 localStorage key（`agent-spaces:cli-panel:<sessionId>`），交给 `FlexLayoutShell` uncontrolled 模式自管
3. **CLI 执行**：开终端后 `ws.send('terminal.input', { sessionId, data: cmd + '\n' })`
4. **默认终端**：复用现有 `SingleTerminal`

## 改动清单

### 1. 新建 `packages/web/src/stores/cli-sessions.ts`（zustand store）

```ts
export interface CliSession {
  id: string;            // crypto.randomUUID()
  name: string;          // 默认 "Session N"，可重命名
  createdAt: number;
}
interface CliSessionsState {
  sessions: CliSession[];
  activeId: string | null;
  createSession: (name?: string) => string;   // 返回新 id，并切到 active
  removeSession: (id: string) => void;        // 同步清理对应 localStorage key
  renameSession: (id: string, name: string) => void;
  setActive: (id: string | null) => void;
}
```
- 初始从 `localStorage["agent-spaces:cli-sessions"]` 读取恢复；变更时写回
- `removeSession` 同时 `localStorage.removeItem("agent-spaces:cli-panel:" + id)`，避免残留

### 3. 新建 `packages/web/src/components/cli/cli-launcher.tsx`（CLI 下拉）

- 按钮：`<Plus>` 图标

### 4. 新建 `packages/web/src/components/cli/cli-panel.tsx`（cli-panel 内容）

- 从 `useCliSessionsStore` 读 `activeId`
- **无激活会话**：渲染空态「请先在左侧创建/选择一个 CLI 会话」
- **有激活会话**：渲染 `<FlexLayoutShell>`（uncontrolled 模式）：
  - `storageKey = "agent-spaces:cli-panel:" + activeId`
  - `defaultLayout`：一个 `{ type: 'tab', name: 'Terminal', component: 'single-terminal' }` 的单 tabset
  - `addableComponents = [{ key: 'single-terminal', name: 'Terminal', icon: <TerminalSquare/> }]`（保留 shell 自带「+」加普通终端）
  - `components = { 'single-terminal': (node) => <SingleTerminal workspaceId={workspaceId} boundDirs={boundDirs} node={node} /> }`
  - `headerEnd = <CliLauncher onPick={handlePickCli} />`：在工具栏右侧追加 CLI 启动按钮
  - `key={activeId}`：会话切换时整个 FlexLayoutShell 重新挂载（每个会话读自己的 localStorage）
- `handlePickCli(command: string)`：
  - 通过 `layoutRef.current?.addTabToActiveTabSet({ component: 'single-terminal', name: 'Terminal', config: { pendingCommand: command }, enableClose: true })` 加 tab
  - 注意：flexlayout 的 `addTabToActiveTabSet` 接受 `config` 字段，会被写入 node.getConfig()

### 5. 改造 `packages/web/src/components/terminal/single-terminal.tsx`

- 创建终端 effect 内，在 `restoreHandled = true` 后**两个分支都**加：
  ```ts
  const pendingCommand = (node.getConfig() ?? {}).pendingCommand as string | undefined;
  if (pendingCommand) {
    // 等终端就绪后输入命令
    setTimeout(() => ws.send('terminal.input', { sessionId, data: pendingCommand + '\n' }), 100);
    // 清除 pendingCommand，避免后续重连重复执行
    node.getModel().doAction(Actions.updateNodeAttributes(node.getId(), { config: { ...(node.getConfig() ?? {}), pendingCommand: undefined } }));
  }
  ```
- 之所以放在 restoreHandled 之后：保证会话已创建/恢复、终端 ready，避免命令丢失

## 数据流总览

```
[cli-list]
  createSession() ──> zustand store: sessions[], activeId
  click item       ──> setActive(id)
                                           │
                                           ▼
[cli-panel]  读 activeId
  ├─ 无 activeId  → 空态
  └─ 有 activeId  → <FlexLayoutShell storageKey="agent-spaces:cli-panel:<id>">
                      ├─ 默认 single-terminal
                      ├─ 工具栏「+」→ 加 single-terminal
                      └─ headerEnd <CliLauncher>
                          └─ 点 CLI → addTabToActiveTabSet({config:{pendingCommand}})
                                          │
                                          ▼
                        <SingleTerminal node> 读 node.getConfig().pendingCommand
                                          │
                                          ▼
                        ws.send('terminal.input', cmd+'\n')
```

## 影响范围与风险

- **localStorage 隔离**：`agent-spaces:cli-panel:<sessionId>` 由 FlexLayoutShell 自管，切换会话靠 `key={activeId}` 强制重挂载，状态不会串
- **老用户布局迁移**：通过模仿 353-358 行的注入逻辑保证新 tab 可见
- **SingleTerminal 改动最小**：只加 pendingCommand 读取逻辑，现有功能不受影响（pendingCommand 默认 undefined）
- **不污染 terminal store**：SingleTerminal 用 `SINGLE_TERMINAL_PREFIX` 前缀，天然被多 tab store 过滤

## 验收步骤指南

1. `pnpm dev` 启动 web，打开工作空间
2. 左侧应看到新 tab「CLI Sessions」，右侧看到「CLI」
3. 在 CLI Sessions 点「+ New Session」→ 列表出现一项，自动激活
4. 切到右侧 CLI tab → 看到一个默认 Terminal（可输入命令验证可用）
5. 工具栏点「+」→ 能再加一个 Terminal，关闭后重开仍在
6. 点工具栏右侧 CLI 启动按钮 → 下拉展示已检测的 CLI；点其中一个 → 新 Terminal 自动执行该 CLI 命令（如 `claude` 直接进入）
7. 切换会话：左列表点另一项 → 右侧布局独立、终端独立
8. 刷新页面 → 会话列表、激活会话、每个会话的布局/终端都恢复
9. 删除会话 → 列表移除，对应 localStorage key 被清理
