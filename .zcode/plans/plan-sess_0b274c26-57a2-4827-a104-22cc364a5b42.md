## 实施计划

### 概述
两件事：
1. 把 `team-management-page.tsx:122~179` 的 `TeamFormDialog` 拆成独立组件 `create-team-dialog.tsx`，并参考 `create-issue-dialog.tsx` 增加 `MemberPicker`（选成员）。
2. 在 `team-management-dialog.tsx` header 的【新建团队】按钮旁加一个 dot（`EllipsisVertical`）按钮，点击弹 `DropdownMenu`，菜单项【从工作流导入】→ 打开 `WorkflowListDialog` → 选 workflow → 提取该 workflow 的 `agent_run` 节点的 `data.agent.id` 列表 → 打开 `create-team-dialog` 并回填默认参数（name=workflow.name, description=workflow.description, members=提取的 agent id 列表）。

### 改动文件

#### 1. 新建 `packages/web/src/components/teams/create-team-dialog.tsx`
从原 `TeamFormDialog` 拆出，参考 `create-issue-dialog.tsx` 结构：
- props：`{ open, onOpenChange, mode: 'create'|'edit', loading, agents: AgentConfig[], defaultValues?: { name?, description?, purpose?, visibility?, members? }, editingTeam?: TeamView | null, onSubmit: (data) => Promise<void> }`
- 内部状态：`name / description / purpose / visibility / members`（不再由 page 持有 form state）
- `useEffect`：open 时按 `editingTeam`（编辑模式）或 `defaultValues`（新建/导入模式）回填
- 布局参考 create-issue-dialog：左主表单（name/description/purpose/visibility），右侧 `MemberPicker`（桌面 `lg:w-64`，移动端 `lg:hidden` 折到下方）
- candidates 由 `agents` 经 `getMemberDisplayName` 构造
- `onSubmit` 回传 `{ name, description, purpose, visibility, members }`
- 关闭时清空内部状态

#### 2. 改 `packages/web/src/components/teams/team-management-page.tsx`
- 删除内联 `TeamFormDialog` 函数定义（122~179）
- 删除 page 内的 `form / setForm / dialogMode / dialogOpen` 状态，改为：`createDialogOpen` + `createDialogDefaults` + `editingTeam` 三个状态
- `openCreateDialog()`：设 defaults=空、editingTeam=null、open=true
- 新增 `openCreateDialogWithDefaults(defaults)`：供外层（team-management-dialog）调用，设 defaults、open=true
- `openEditDialog(team)`：设 editingTeam=team、open=true
- `submitTeam(data)`：接收 create-team-dialog 回传的数据，按 mode 调 API（POST 创建带 `initial_members`；PATCH 更新不带 members）；创建时把 `members` 映射为 `initial_members: [{ agent_id, role: 'member' }]`
- `forwardRef` handle 增加暴露 `openCreateDialogWithDefaults`
- 渲染：`<CreateTeamDialog ... />` 替换原 `<TeamFormDialog />`

#### 3. 改 `packages/web/src/components/teams/team-management-dialog.tsx`
- header 内【新建团队】按钮旁加 `DropdownMenu`：
  - `DropdownMenuTrigger` = `Button variant="ghost" size="icon"` + `EllipsisVertical` 图标
  - `DropdownMenuItem`【从工作流导入】
- 点击菜单项 → 打开 `WorkflowListDialog`（`showCreate={false}`，单选 `onSelect`）
- `useWorkflowStore` 获取 workflows 传入；open 时 `loadWorkflows()`
- `onSelect(workflow)`：提取 `workflow.nodes.filter(n => n.type === 'agent_run')`，取 `data.agent.id`（字符串且非空）去重 → 构造 defaults `{ name: workflow.name, description: workflow.description ?? '', members: [...] }` → 关闭 WorkflowListDialog → 调 `pageRef.current?.openCreateDialogWithDefaults(defaults)`
- import `WorkflowListDialog`、`useWorkflowStore`、`DropdownMenu*`、`EllipsisVertical`

#### 4. 文案 `packages/web/src/locales/{zh,en}/teams.json`
新增：
- `importFromWorkflow`：从工作流导入 / Import from workflow
- 复用现有 `dialog.createTitle` 等

### 关键设计点
- **成员映射**：仅取 `agent_run` 节点的 `data.agent.id`（用户明确要求 agent_run 节点）。team 后端对 `agent_id` 无存在性校验，直接透传。
- **create-team-dialog 单实例**：放在 page 内，普通新建 / 编辑 / 工作流导入共用，避免多实例叠加。导入流程通过 `pageRef.openCreateDialogWithDefaults` 触发。
- **MemberPicker 仅 create 模式显示成员选择**：编辑模式也显示（与 create-issue-dialog 一致），但 submitTeam 在 edit 模式不提交 members（成员管理非本次范围，保持原 PATCH 行为）。
- **WorkflowListDialog 复用**：`showCreate={false}` 隐藏新建按钮，单选模式 `onSelect`。

### 不改动的部分
- 后端 team API 已支持 `initial_members`，无需改。
- `/teams` 页面（非 embedded）行为不变，新建按钮仍在 page 内。
- 原 MemberPicker / WorkflowListDialog / DropdownMenu 组件本身不改。

### 验收
1. 打开团队管理弹窗 → 点【新建团队】→ create-team-dialog 弹出，右侧有 MemberPicker 可选 agent。
2. 点 header dot 按钮 → dropdown → 【从工作流导入】→ WorkflowListDialog 弹出 → 选一个含 agent_run 节点的 workflow → create-team-dialog 打开，name/description 已填、members 已勾选 workflow 里的 agent。
3. 提交创建 → 团队列表刷新，新团队含选中成员。
4. 编辑团队 → create-team-dialog 回填现有字段。
5. `pnpm exec tsc --noEmit` 通过。
