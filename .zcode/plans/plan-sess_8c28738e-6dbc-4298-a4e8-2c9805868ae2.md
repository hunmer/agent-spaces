## 实现方案：前端图片压缩 + 修复 AI 框错位 bug

### 决策汇总
- **压缩库本地化**：browser-image-compression 下载到 `vendor/`，走现有 `loadVendor` + `(0,eval)` 全局求值（与 fabric 同款，UMD 格式 `e.imageCompression=t()`）。CDN 在 webpack/turbopack 下不可靠（handoff.md 记录）
- **bug 根因**：AI 返回的 coords 基于「AI 看到的图」尺寸，画布背景图是 `loadImageSource` 加载的图。两者尺寸不同 → `getBBoxBasis` 的 `sx` 换算错误 → 框错位
- **修复策略（方案 A）**：压缩后同步更新画布背景图为压缩图，保证 AI 图与画布图严格 1:1 对应，坐标零换算

### bug 根因详解
```
当前流程：
1. imageUrlToDataUrl(imageUrl)  → 原图 base64 传 AI
2. loadImageSource(imageUrl)    → 原图作画布背景
3. AI 返回 coords（基于原图）→ applyJsonData → sx = 原图宽/basis.w

加压缩后若不同步：
1. compress(原图) → 压缩图 base64 传 AI
2. loadImageSource(原图) → 原图作画布背景  ← 尺寸不一致！
3. AI 返回 coords（基于压缩图）→ sx = 原图宽/压缩图basis → 错位
```
**正解**：压缩后用压缩图同时更新画布背景 + 传 AI，保证 sourceRef 与 AI 输入完全同源。

### 改动文件清单（全部 mini-app src，刷新即生效，无宿主改动）

#### 1. `src/vendor/browser-image-compression.js`（新增，~95KB）
从 `https://cdn.jsdelivr.net/npm/browser-image-compression@2.0.2/dist/browser-image-compression.js` 下载。UMD 格式。

#### 2. `src/utils/image-ops/cdn.js`
新增 `getImageCompression()` 加载器：
```js
export async function getImageCompression() {
  if (window.imageCompression) return window.imageCompression;
  const AS = window.AgentSpaces;
  const url = AS.srcFileUrl(VENDOR_BASE + 'browser-image-compression.js');
  const code = await (await fetch(url)).text();
  (0, eval)(code);  // UMD: e.imageCompression=t() → window.imageCompression
  if (!window.imageCompression) throw new Error('imageCompression 加载失败');
  return window.imageCompression;
}
```
与 `getFabric` 同款 eval 模式。

#### 3. `src/components/BBoxViewerDialog.jsx`（核心改动）
**新增辅助函数 `compressToDataUrl(url)`**：
- fetch 原图 → File
- `imageCompression(file, { maxSizeMB: 1, maxWidthOrHeight: 1920, useWebWorker: true })` → 压缩 File
- FileReader 转 data URL
- 返回 `{ dataUrl, blob }`（blob 用于更新画布背景）

**改造 `handleAiAnalyze`**：
1. 压缩图：`const { dataUrl } = await compressToDataUrl(imageUrl)`
2. 用压缩 dataUrl **重新加载 sourceRef**：`sourceRef.current = await loadImageSource(dataUrl)`
3. 用压缩 dataUrl **更新 fabric 背景图** + 重新 fitToStage
4. 传压缩 dataUrl 给 AI（images 参数）
5. AI 返回 → applyJsonData（此时 sourceRef 与 AI 图同源，坐标严格对应）

**状态提示增强**：压缩阶段显示「✨ 压缩图片中…」，让用户感知 Web Worker 工作。

#### 4. 新增「自动压缩」开关（可选，加到工具条）
- `autoCompress` state（默认 true）
- 开关关闭时跳过压缩直接传原图（兼容极端情况：压缩后识别率下降）

### 关键技术点
1. **UMD eval 加载**：browser-image-compression 是 `!function(e,t){...e.imageCompression=t()}(...)` UMD，与 fabric 同款 `(0,eval)(code)` 全局求值，`window.imageCompression` 可用
2. **Web Worker 不卡 UI**：`useWebWorker:true` 把 Canvas 绘制 + 量化移出主线程，大图（4K+）压缩时 UI 仍流畅
3. **坐标同源保证**：压缩后 `loadImageSource(dataUrl)` 重建 sourceRef（canvas.width = 压缩图宽），AI 基于同尺寸返回 coords → `getBBoxBasis` 的 `sx = 压缩图宽/coords最大值`，若 AI 按该尺寸返回像素值则 sx=1，零换算
4. **背景图同步**：`fabric.Image.fromURL(dataUrl)` 替换 backgroundImage + fitToStage，视觉上画布显示压缩图（用户无感，因压缩质量高）

### 验收要点
- AI 分析时状态显示「压缩图片中…」→ UI 不卡顿（Web Worker）
- 压缩后画布背景图清晰度可接受（maxWidthOrHeight:1920 + maxSizeMB:1）
- **AI 返回的框与图片内容完全吻合**（按钮/文字/图标位置准确，不错位）
- 关闭「自动压缩」开关 → 直接传原图，流程正常（可能稍慢）
- 断网/压缩失败 → 降级传原图（catch 后 fallback）

### 不做的事
- 不改宿主层（压缩纯前端，images 参数已支持 base64）
- 不把压缩库加 allowlist（走 vendor eval，与 fabric/jszip 一致）
- 不暴露压缩参数到 UI（maxSizeMB/maxWidthOrHeight 固定合理默认值）
