# Skills Package（技能包商店）实现方案

## 目标
新增第十类商店资源 **skillspackage**（技能包）。每个包 = 一个 agent 预设 + 若干私有 skill。用户从侧边栏入口打开商店，点安装后：
1. 创建一个 agent 模板（保存到 `agent-spaces-data/agent-templates/{agentId}/agent.json`）
2. 把 `PROMPT.md` 转成 `systemPrompt` 写入 `agent.json`
3. 用 slug 作为 `templateId` 避免重复导入
4. 解压包内每个 `skills/*.zip` 到该 agent 的 `agent-templates/{agentId}/skills/{skillSlug}/`
5. 把这些 skill 名写进 `agent.json` 的 `skills` 字段（即「开启对应 skill」）

## 决策确认（已与用户对齐）
- 索引字段：`{ id, name, summary, skillSlugs, skillCount, zipUrl, md5, updatedAt }`
- 打包：generate-index 时把整个包目录压成 `{slug}.zip`，前端一次下载一个 zip
- skill 只装到 agent 模板私有目录，不进全局 skills
- 入口：manage 折叠组下「技能包」，放在 skills 子项之后

## 改动清单（10 处）

### A. 模板库（packages/templates/）

#### A1. `generate-index.mjs` — 新增 `scanSkillsPackageStore()` + 整包 zip 化
- 新增函数 `scanSkillsPackageStore()`：
  - 遍历 `skillspackage/` 下每个子目录（如 `media-storyboard-design`）
  - 读 `manifest.json` → 取 `slug`/`displayName`/`summary`/`skillSlugs`
  - 用 `folderMD5` 算指纹，沿用现有 `updatedAt` 复用逻辑
  - 调用 `arch zip`（node:zlib + 手写 store 打包器，或直接用已有的 `readZipEntries` 反向逻辑）把整个目录打成 `{slug}.zip` 写到 `skillspackage/{slug}.zip`；若 zip 已存在且 md5 一致则跳过重打包
  - 产出 `{ id: slug, name: displayName, summary, skillSlugs, skillCount: skillSlugs.length, zipUrl: 'skillspackage/{slug}.zip', md5, updatedAt }`
  - 写 `skillspackage/index.json`
- 在文件末尾调用处加上 `scanSkillsPackageStore();`
- **打包实现**：写一个 `writeZip(dir, outPath)` 辅助函数（store 模式，无压缩，zero-dep，参考已有 `readZipEntries` 的逆操作）。zip 结构：`{slug}/manifest.json`、`{slug}/PROMPT.md`、`{slug}/skills/*.zip`（保留目录前缀，便于服务端定位）。

### B. 后端（packages/server/）

#### B2. `src/services/skills-package.ts` — 新建服务（核心安装逻辑）
关键函数 `installSkillsPackage(zipBuffer: Buffer): { agent: AgentConfig; skills: string[] }`：
1. 解压 zip 到临时目录（复用 `mini-apps.ts` 的 `extractZip` 模式，或抽出共享 helper）
2. 找到 `{slug}/manifest.json` 读 `slug`/`displayName`/`summary`/`skillSlugs`，读 `{slug}/PROMPT.md` 作 systemPrompt
3. **去重**：用 `listTemplates()` 查是否已有 `templateId === slug` 的 agent；有则复用其 id（更新），无则新建 uuid
4. **解压 skill zips**：对 `{slug}/skills/*.zip` 逐个解压到 `agent-templates/{agentId}/skills/{zipBasename}/`（zip 内 SKILL.md 在根目录，解压后正好 `{skillSlug}/SKILL.md`）
5. **写 agent.json**：构造 AgentConfig，`systemPrompt = PROMPT.md 内容`，`skills = skillSlugs`（来自 manifest），`templateId = slug`，`role='agent'`，`runtimeKind='claude-code'`，`modelProvider='anthropic-messages'`，默认 model；调 `writeAgentTemplate(preset)` 落盘（现有函数已会建 skills 目录、但我们的 skill 来自 zip 不在全局，需在调它之前手动解压好，且 preset.skills 只放 slug 名让它「开启」）

依赖：复用 `getDataDir`、`writeAgentTemplate`（从 agent.ts export）、`extractZip`（从 mini-apps.ts 抽公共或本地重写）。

#### B3. `src/routes/skills-package.ts` — 新建路由
- `POST /api/skills-packages/install`：接收 `{ zipUrl }`（前端传商店 zip 的相对路径）或 `{ zipBase64 }`（前端 fetch 后传 buffer）。**推荐 `{ zipUrl }`**，后端自己 fetch + 解析，前端代码最简。
  - 用 `fetch(storeBase + zipUrl)` 拉 zip buffer → 调 `installSkillsPackage`
  - 返回 `{ agent, skills }`
- 在 `src/app.ts` 挂载：`app.use('/api/skills-packages', skillsPackageRouter)`（参考其他路由挂载位置）

## 关键技术细节

### zip 打包（A1）
generate-index 里写一个 `writeStoreZip(dir, outPath, prefix)`：遍历目录收集 `[relPath, content]`，按 ZIP store 格式手写 local header + central directory + EOCD（CRC32 用 node:zlib 的 `crc32` 或手写）。和现有 `readZipEntries` 对称。**备选**：若手写打包风险高，改用 `archiver`（需加依赖）—— 但 templates 包目前 zero-dep，倾向手写 store 模式（无压缩，逻辑简单可靠）。

### 去重（B2）
复用 `AgentConfig.templateId`：workflow 已用此字段去重，语义完全契合「这个 agent 来自 skillspackage/{slug}」。

### skill 开启（B2）
`agent.json` 的 `skills: string[]` 字段就是「开启的 skill 列表」。把 manifest 的 `skillSlugs` 原样写入即可。skill 文件已解压到 agent 目录下，运行时 `getAvailableSkillNames` 会检测到。

### 现有 `writeAgentTemplate` 的坑
它内部会尝试从**全局** skills 目录拷贝 skill 到 agent 目录（agent.ts:716）。我们的 skill 来自 zip 不在全局目录，拷贝会落空但不会报错（只是写个空文件）。**对策**：在调 `writeAgentTemplate` 之前，先把 zip 解压好的 skill 目录就位；由于 `writeAgentTemplate` 会 `rmSync(skillsDir, recursive)` 再重建，会冲掉我们解压的内容。**最终对策**：不调 `writeAgentTemplate`，而是直接手动写 `agent.json` + 解压 skill 目录（绕开它的 skills 同步逻辑），逻辑更可控。
