## Detailed Description

### Workflow_Editor_Execution_Sync.md Workflow_Editor_Execution_Sync.md

This document serves as a comprehensive reference guide analyzing the frontend workflow editor's execution synchronization logic and identifying a critical scope mismatch in event broadcasting. The main sections covered include the editor's execution responsibilities, WebSocket connection model, state management approach, snapshot handling, event subscriptions, execution history preview, and a detailed analysis of the proven scope mismatch issue. Key topics include how the editor initiates execution, maintains WebSocket connections, manages execution state locally, and processes server events.

The document highlights several important architectural aspects: the frontend uses a single WebSocket instance per workspaceId, maintains local execution state via hooks and Zustand stores, and handles execution history through REST APIs. A fundamental architectural gap is identified where execution events lack a unified broadcasting scope model, currently using inconsistent workspaceId, 'workflows' string, or workflowId without clear contract.

This technical reference is intended for developers working on workflow editor functionality, requiring knowledge of React, WebSocket handling, and the project's frontend architecture. The document serves both as a technical reference and a problem statement for resolving the execution event scope inconsistency.
