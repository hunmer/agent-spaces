# workflow_插件开发指南

This directory serves as a comprehensive development guide for creating plugins for the workflow platform, covering core concepts like API extension, multi-language configuration, plugin architecture, and local testing setup. It targets developers building plugins for workflow, which supports both Electron and web clients, and provides detailed instructions on server/client plugin distinctions, configuration management, and best practices. The guide includes reference implementations and code snippets to help developers integrate plugins effectively, with a focus on maintaining compatibility and user experience across different client types.

## Detailed Description  
### api.js_6more_fa68a04c.md api.js_6more_fa68a04c.md  
This document focuses on API extension and client integration for workflow plugins. It explains how to extend default APIs via `api.js`, load text-based view templates in `view.js`, define Web client manifests using `entries.client`/`entries.view` URLs, and manage configurations through `info.json` (accessed via `context.config`). Key best practices include preferring server plugins, using `manifestUrl` for web clients, and avoiding unnecessary client plugins. The guide includes reference implementations for server, Electron client, and Web client plugins, making it essential for developers working with API or UI integration.  

### 多语言配置.md 多语言配置.md  
This guide details multi-language support configuration for server plugins. It covers the purpose of localization, what content to translate (e.g., workflow labels, property tooltips) versus what to avoid (debug logs), and the structure of `lang.json` with locale-specific keys and fallbacks. Two implementation methods are explained: the recommended action factory function approach and a direct `context.t` alternative. Best practices emphasize stable English keys, English fallbacks to prevent blank UI, and dynamic language switching via factory functions. It is intended for developers needing to localize user-facing text in their plugins.  

### workflow_插件开发指南_7more_84f3cd0c.md workflow_插件开发指南_7more_84f3cd0c.md  
This document outlines the plugin development process for workflow, distinguishing between server and client plugin types. It covers directory structure (e.g., server plugins include `main.js`/`workflow.js`, client plugins include `view.js`/`api.js`), `info.json` configuration (id, name, version, type, hasWorkflow, entries), and core file functions: `main.js` for lifecycle management (activate/deactivate), `workflow.js` for defining workflow nodes, and `tools.js` for Agent tools. Targeted at developers new to workflow plugins, it provides a clear roadmap for structuring and configuring plugins.  

### 本地测试环境/  
This subdirectory contains two documents focused on plugin testing and configuration. One guides developers on setting up a local test environment, including multi-file tool entry structures and Workflow Node/Agent Tool reuse. The other explains form attribute field type configuration, clarifying the distinction between `type` and `dataType` and their usage rules. It addresses practical challenges like tool reuse and data type mapping, making it valuable for developers configuring plugins or testing workflows.
