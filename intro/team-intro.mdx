# Team：让多个 Agent 像一个团队一样干活

## 痛点

你是不是也遇到过这种情况？

一个稍微复杂点的需求，单靠一个 Agent 根本搞不定。

让一个通用 Agent 又写前端、又调接口、又写文档，结果哪一样都不专业，还经常上下文爆掉、半路跑偏。

于是你只能手动接力：先让 A Agent 出页面，再把它的结果复制给 B Agent 写接口，最后再喂给 C Agent 写文档。

每一步都要你盯着、复制粘贴、对齐格式、检查有没有遗漏。你以为自己在用 AI 提效，其实是在给 AI 当搬运工。

更头疼的是，一旦中间某一步出了问题，你得从头再来，因为没有一个地方能把这些 Agent 的协作过程完整记下来。

**问题不在于 Agent 不够强，而在于没有一个机制把它们组织起来分工协作。**

## 解决方案

Team 就是来解决这个问题的。

它把多个 Agent 组成一个团队，让它们像真人团队一样分工、交接、交付。

你只需要做一件事：把任务交给 Team 的 owner。

接下来发生的事情，是这样的：

- **owner 拆任务** — owner 拿到你的需求，自动拆解成一个个子任务
- **分配给专业成员** — 每个子任务派给最合适的 Agent，比如前端 Agent、后端 Agent、文档 Agent
- **成员各自完成** — 每个 Agent 只做自己最擅长的那一块，不串味、不跑偏
- **接力交付** — 一个成员做完，把结果交给下一个，全程自动衔接
- **owner 收口** — 所有成员完成后，owner 把成果汇总成最终交付物交给你

整个过程被完整记录在一个会话里：谁做了什么、调用了哪些工具、产出了什么，一目了然，随时可查。

## 为什么比手动接力强

| 手动接力 | Team 协作 |
|----------|-----------|
| 你当搬运工，复制粘贴对齐格式 | Agent 之间自动交接，你只看结果 |
| 一个 Agent 干所有事，哪样都不精 | 每个 Agent 只做自己擅长的，专业 |
| 中间出错从头再来 | 任务有状态，谁完成谁失败清清楚楚 |
| 过程没记录，复盘靠记忆 | 全程留痕，会话、任务、日志可追溯 |
| 上下文越堆越乱，容易跑偏 | 按会话隔离，每个任务边界清晰 |

## 适合什么场景

只要你发现「这事一个 Agent 搞不定，得几个人配合」，就适合用 Team：

- 🎨 **出完整产品** — 前端出页面 + 后端出接口 + 文档写说明
- 🔧 **大型重构** — 一个 Agent 改不了整个系统，但拆成模块就能各管一摊
- 📊 **数据项目** — 采集 + 清洗 + 分析 + 可视化，每个环节一个专家
- 📝 **内容生产** — 选题 + 写稿 + 配图 + 排版，流水线作业

## 上手有多简单

不用写代码，不用懂编排。

打开 Teams 页面，创建一个 Team，把你要用的 Agent 加进来，告诉 owner 你要什么，剩下的事交给它们。

从「一个人指挥一堆 Agent」升级到「一个 Team 自动协作」。

**把协作这件事，交给 Team。**
